O reel de "N peças", com o rosto real do Nei

Você escreve um roteiro.json; o rtex devolve um reel vertical 1080×1920: a tese escrita no quadro 0, as peças numeradas com índice, prova com fonte, a ressalva honesta e um único pedido, "comenta PALAVRA". Quem fala é o avatar do Nei no HeyGen.

Em resumo

O rtex é o motor que o Nei usa para fazer reels (vídeos curtos verticais) do INEMA com o próprio rosto: o avatar dele no HeyGen fala o roteiro, e o motor desenha por cima as telas, a legenda palavra por palavra e o cartão final. Cada vídeo segue um formato fixo de "N peças", do quadro de abertura com a tese até o pedido "comenta PALAVRA". Um validador, um crítico automático e um QA conferem o formato antes de publicar. O código é aberto para estudar e adaptar; para gerar o seu vídeo, você precisa do seu próprio avatar no HeyGen, além de Python, Node, ffmpeg e Whisper.

O que é

Um formato fixo, com o apresentador de verdade

Dois terços de cima são do conteúdo, o terço de baixo é do Nei falando, o reel inteiro. Todo número tem fonte na tela, e o amarelo aparece como superfície uma única vez: na palavra que o vídeo pede para comentar.

🎙️ Avatar real do Nei

A fala vai ao estúdio do HeyGen pela assinatura; o vídeo do avatar volta, o Whisper marca o tempo de cada palavra e o motor encaixa telas e legenda nesse tempo.

🧩 Padrão de peças

Tese no quadro 0, prova social com número, "N peças" com índice visível, método numerado, prova, ressalva, máxima depois de um silêncio e "comenta PALAVRA".

✅ Três conferências

O validador cobra a regra; um crítico (claude -p) dá nota ao roteiro; o QA mede duração, ritmo, volume, mudanças de tela por minuto, silêncio, cartão final e o amarelo.

O formato

Os nove blocos do padrão rtex

Nesta ordem. O comando checar reprova o roteiro se um bloco obrigatório faltar ou vier fora do lugar.

  1. tese: escrita no quadro 0 (até 9 palavras, a palavra-isca em destaque), com algo se mexendo no 1º segundo.
  2. autoridade: prova social com número; o contador pousa no valor da fonte.
  3. problema: a dor mostrada com um objeto (no exemplo, um chat sendo riscado).
  4. virada: "N peças" anunciadas; o índice 01–N aparece antes do 1º item e vira pílulas no topo.
  5. metodo: os itens numerados, um objeto por item, rótulo "0N / NOME".
  1. prova: um fato com fonte que confirma o que veio antes.
  2. ressalva: as limitações, faladas e legíveis, viradas em instrução.
  3. maxima: antítese curta, depois de 0,6–0,75 s de silêncio (voz e trilha somem).
  4. cta: "comenta PALAVRA", a mesma palavra da tese; o cartão fica 9 s depois da última palavra.

Glossário rápido

Palavra-isca

A palavra que o vídeo pede para comentar (aqui, PASTA). É a tese, aparece no quadro 0 e é a única pílula amarela do vídeo.

Máxima

A frase-resumo do fim, em antítese ("Não é a IA que é burra. É a pasta que está vazia."), depois de um silêncio curto.

Palco

A página motor/palco.html que desenha as telas. O render filma essa página a 30 quadros por segundo.

HeyGen e estúdio

HeyGen é o serviço que gera o vídeo do avatar falando. O rtex usa o estúdio (o site, pela assinatura), num navegador aberto na tela virtual :99.

Legenda karaokê

A legenda acende palavra por palavra no tempo da fala, com as palavras-chave coloridas.

LUFS

Medida de volume percebido. −14 LUFS é o volume que as redes usam como padrão.

CTA

"Chamada para ação": o pedido final do vídeo. Aqui é um só, "comenta PALAVRA".

Whisper e Playwright

Whisper transcreve a voz e dá o tempo de cada palavra. Playwright abre o palco num navegador e filma cada quadro.

Crítico e revisor

O crítico é um claude -p que dá nota a cada bloco do roteiro. O revisor independente é outra sessão, que só olha o resultado.

Como funciona

Do roteiro ao video.mp4

O rtex.py roda cada passo. O avatar é a parte lenta: o estúdio pode levar de minutos a horas para entregar o vídeo.

roteiro.json→ checar→ critico→ avatar-enviar (HeyGen)→ prints→ avatar + Whisper→ cena→ render (30 fps, −14 LUFS)→ qa→ video.mp4
1

Roteiro conferido

checar cobra ordem dos blocos, índice = método, fala sem algarismo nem "!", fonte em todo número, isca = tese e duração estimada de 60–90 s. critico dá a nota.

2

Avatar e tempo

A fala vai ao estúdio; o vídeo volta, o Whisper marca as palavras, a fala é acelerada até ~182 palavras/min (no máximo 12%) e entra o silêncio antes da máxima.

3

Cena, render e QA

cena liga cada tela a uma palavra da fala; render filma o palco, põe o avatar embaixo e a trilha; qa mede tudo e monta a folha.

Pré-requisitos

O que precisa estar na máquina

O motor foi feito para a máquina do Nei (Linux). Os caminhos abaixo estão no código; numa máquina diferente, use as variáveis citadas ou ajuste o arquivo.

Avatar: HeyGen pelo estúdio

Uma conta HeyGen com o seu avatar e a sua voz. Uma vez só: (1) faça login num perfil do navegador do Playwright; (2) no estúdio, crie um projeto de vídeo com o nome exato TEMPLATE-AVATAR16 (ou outro em RTEX_HEYGEN_TEMPLATE), com o seu avatar e a sua voz: o motor abre esse projeto, faz "editar como novo" e troca a fala; (3) ponha a sua chave da API do HeyGen no arquivo que o download lê (caminho fixo no heygen/heygen-estudio-baixar.mjs; ela só consulta o status e baixa o vídeo).

npx playwright open --user-data-dir ~/.cache/inemaccbot/perfil-heygen https://app.heygen.com   # login; ou outro dir em RTEX_HEYGEN_PERFIL
mkdir -p ~/projetos/openpcbotv2
echo "HEYGEN_API_KEY=sua-chave" >> ~/projetos/openpcbotv2/.env

Whisper (inemavox)

O inematds/inemavox em ~/projetos/inemavox (ou outro caminho em CS_INEMAVOX). O rtex tenta o Whisper residente na porta 7871 e, sem ele, roda o transcrever_v1.py do inemavox com o large-v3 (cerca de 10 GB na placa de vídeo NVIDIA). O Python do Whisper residente vem de CS_WHISPER_PY; o padrão aponta para um ambiente conda chatterbox da máquina do Nei, então aponte para o seu.

git clone https://github.com/inematds/inemavox ~/projetos/inemavox
# dependências: ver o README do inemavox
export CS_WHISPER_PY=/caminho/do/seu/python3

Node, ffmpeg, Python

Node 18+, ffmpeg com ffprobe, Python 3 com Pillow e numpy, um servidor X virtual na tela :99 (ex.: Xvfb) para o render, e a CLI claude logada para o crítico.

git clone https://github.com/inematds/rtex
cd rtex
npm i
npx playwright install chromium
pip install --user pillow numpy   # ou dentro de um venv
Xvfb :99 -screen 0 1920x1080x24 &   # se ainda não houver
Caminho mais curto, sem o estúdio: se você já tem um vídeo 16:9 (1920×1080) de você ou do seu avatar falando o roteiro, pule o HeyGen inteiro: python3 rtex.py fazer <pasta> --de seu-video.mp4. A fala do vídeo precisa bater com a do roteiro em pelo menos 85% (o motor confere com o Whisper).
Opcionais: enviar manda o vídeo ao bot do Telegram do Nei (bin/enviar_bot_v3.mjs) e fila põe o vídeo na fila de publicação do r7ex (~/projetos/r7ex/fila/fila.py, ou RTEX_FILA). Fora da máquina do Nei, pare no qa e publique como preferir.
Guia de uso · passo a passo

Do tema ao vídeo conferido

Cada edição mora em edicoes/<data>-<slug>/. O atalho fazer (passo 9) roda checar, prints, avatar, cena, render e qa de uma vez.

1

Crie a edição você

Copia o roteiro modelo (a 1ª edição) para uma pasta nova com a data de hoje.

python3 rtex.py novo minha-edicao   # -> edicoes/AAAA-MM-DD-minha-edicao/roteiro.json
2

Escreva o roteiro, com as fontes você

Confira cada número na fonte no dia e anote em fontes[] com valor e verificado_em. Depois escreva os blocos (formato em "O roteiro.json"), a fala por extenso e a isca.

3

Valide e passe no crítico

checar é regra pura. critico pede nota a um claude -p pela assinatura: passa sem bloqueio, tese (o gancho) ≥ 8, média ≥ 7,5 e nenhum bloco abaixo de 6. Grava critica.json.

python3 rtex.py checar  edicoes/AAAA-MM-DD-minha-edicao
python3 rtex.py critico edicoes/AAAA-MM-DD-minha-edicao
4

Libere e envie o avatar você

O envio só sai com um OK escrito para esta produção em avatar/APROVADO_HEYGEN (um avatar por reel). Depois do envio a fala fica congelada: erro de texto se corrige na legenda (campo trocas do roteiro), não num segundo avatar.

mkdir -p edicoes/AAAA-MM-DD-minha-edicao/avatar
echo "ok para este reel" > edicoes/AAAA-MM-DD-minha-edicao/avatar/APROVADO_HEYGEN
python3 rtex.py avatar-enviar edicoes/AAAA-MM-DD-minha-edicao   # grava avatar/video_id.txt
5

Tire os prints das páginas

Prints reais das páginas do GitHub citadas e os logos. Abra e leia os prints antes de seguir.

python3 rtex.py prints edicoes/AAAA-MM-DD-minha-edicao
6

Prévia sem avatar opcional

Enquanto o estúdio trabalha, numa cópia da pasta: tempos sintéticos, cena e alguns quadros soltos (em segundos). Acha erro de layout antes do avatar chegar. A prévia não chama o estúdio nem gasta outro avatar.

cp -r edicoes/AAAA-MM-DD-minha-edicao /tmp/previa
python3 ferramentas/tempos_sinteticos.py /tmp/previa
python3 rtex.py cena /tmp/previa
node motor/render.mjs /tmp/previa --quadros 1,10,20
7

Baixe o avatar e acerte o ritmo

avatar-conferir faz uma consulta (pronto ou processando). avatar espera, baixa, marca as palavras com o Whisper, acelera a fala até ~182 palavras/min, põe o silêncio antes da máxima e os 9 s de cartão.

python3 rtex.py avatar-conferir edicoes/AAAA-MM-DD-minha-edicao
python3 rtex.py avatar edicoes/AAAA-MM-DD-minha-edicao
python3 rtex.py avatar edicoes/AAAA-MM-DD-minha-edicao --de avatar.mp4   # reaproveitar um mp4
8

Cena, render e QA

O palco a 30 fps, o avatar no terço de baixo, a trilha e −14 LUFS em duas passadas; o QA grava build/qa.json e a folha build/folha.jpg com 16 quadros.

python3 rtex.py cena   edicoes/AAAA-MM-DD-minha-edicao
python3 rtex.py render edicoes/AAAA-MM-DD-minha-edicao   # -> video.mp4
python3 rtex.py qa     edicoes/AAAA-MM-DD-minha-edicao
9

Ou tudo de uma vez

checar → prints + avatar → cena → render → qa (o envio ao estúdio, passo 4, vem antes).

python3 rtex.py fazer edicoes/AAAA-MM-DD-minha-edicao
10

Olhe, revise e entregue você

Leia a folha e o qa.json; peça uma revisão a quem não escreveu o roteiro. O que a isca promete tem de existir no dia. Na máquina do Nei, enviar manda ao bot e fila põe na fila do canal (nunca upload direto).

python3 rtex.py enviar edicoes/AAAA-MM-DD-minha-edicao
python3 rtex.py fila   edicoes/AAAA-MM-DD-minha-edicao
O roteiro.json

O formato do roteiro, em uma tela

Trecho real da 1ª edição, encurtado (as linhas // não são JSON válido; o arquivo completo está em modelo/roteiro.json).

{
  "versao": "rtex/1", "tema": "5 peças de IA do mês — a melhor é uma pasta",
  "isca": { "palavra": "PASTA", "entregavel": "os 5 links e o curso do inema.club..." },
  "fontes": [ { "id": "ecc", "url": "https://github.com/affaan-m/ECC", "valor": "291 mil", "verificado_em": "2026-10-28" } ],
  "trocas": { "é cê cê": "ECC", "cinco peças": "5 peças" },
  "blocos": [
    { "tipo": "tese", "fala": "A melhor peça de IA deste mês é só uma pasta. E a quarta nem é de IA.",
      "tela": { "linhas": ["5 PEÇAS DO MÊS.", "A MELHOR É UMA PASTA."], "destaque": "PASTA" },
      "objeto": { "comp": "tese" } },
    // ... autoridade, problema, virada ...
    { "tipo": "metodo", "n": 1, "nome": "PASTA", "fonte": "skills",
      "fala": "Um: as Skills do Claude. Uma pasta por tarefa, com o processo, os modelos e a checklist.",
      "objeto": { "comp": "pasta", "params": { "titulo": "Skills do Claude" } } },
    // ... metodo 2–5, prova, ressalva ...
    { "tipo": "maxima", "fala": "Não é a IA que é burra. É a pasta que está vazia.", "objeto": { "comp": "maxima" } },
    { "tipo": "cta", "fala": "Comenta pasta que eu te mando os cinco links, com o curso do inema ponto club.",
      "objeto": { "comp": "isca", "params": { "palavra": "PASTA" } } }
  ]
}

Campos principais

tipo (a ordem dos nove blocos) · fala (por extenso, sem algarismo nem "!") · tela (texto grande e destaque) · objeto.comp + objeto.params (o que o palco desenha) · n e nome nos itens do método (iguais ao índice da virada) · fonte (id em fontes). No topo: trocas (como a fala aparece na legenda), cores (palavras coloridas), ritmo e publicar (título, descrição, canal da fila).

Componentes do palco (objeto.comp)

tese, contador, chat_riscado, indice (com as pílulas de progresso), pasta, repo (print real + estrelas), manchete, selo_prova, ressalva, maxima (flash tipográfico) e isca (a pílula amarela com a caixa de comentário).
